# 多次 Vibe Coding 记录

说明：下面每一轮都按「我说的原话 → AI 做了什么 → 我发现了什么 → 下一轮怎么改」记录。原话是直接复制的，AI 的回答我做了压缩，只留结论。记录顺序就是实际发生的顺序。

---

## 第 1 轮：从“照着这个做”开始

**我说的**：

> https://exoticflicker.github.io/cati
> 你去看看这个网页做的“选项测评”，我想在我的 Github 上也做一个这东西

**AI 做的**：把那个页面下载下来拆开看，告诉我它是单文件静态站（一个 HTML 里塞了样式、脚本、动画），24 道题每个选项对应 8 个“猫”之一，最后票数最高的那个就是结果。同时指出了两件事：页面上写着“分享链接会带上结果”，但其实分享的是裸链接；页面上的“已测试人数”和投票挂在一个第三方的免费计数接口上。

**我的判断**：这两个我都认。分享不带结果，等于白写那句话；第三方接口随时会挂，我不想依赖。于是定下来要做真的带结果的分享，并且不接任何外部接口。

**下一轮**：AI 问我做什么主题，我说要“糊弄小女孩心理恋爱的风格，纯娱乐，像塔罗牌那种”。

---

## 第 2 轮：把主题落到内容上

**我说的**：

> 就是这种糊弄小女孩心理恋爱的风格，随便帮我想想主题和题目，不追求客观准确性，纯娱乐产品，就像是小女孩之间玩的那种“塔罗牌”、占卜一样

**AI 做的**：定了“恋爱塔罗”，8 张牌（月亮、太阳、星星、女祭司、皇后、恋人、隐者、魔术师），写了 24 道情景题（已读不回、冷战、暧昧三个月不表态、他和别人聊得开心、生日、同居、见家长、半年后前任发消息），每题 3 个选项，每个选项指向一张牌。还做了一件我没要求的事：让 24 道题里每张牌正好出现 9 次，保证抽到的概率一样。

**我的判断**：题目看着像真人写的，不像模板。8 个原型我一眼能分出谁是谁，这点很重要——如果两个结果描述差不多，整个测试就没意思了。所以我又让它把每张牌的“一句话标题”改得更扎人，比如“月亮 · 夜里想太多的人”。

**踩到的第一个坑**：AI 自己跑自动测试时，每道题都点第一个选项，结果 8 张牌票数完全一样，结果页一次列出 7 条“你身上还带点 XX 的影子”。它把显示上限定成 2 条。我这才知道**并列是常态**，不是异常。

---

## 第 3 轮：部署，第一次拿到链接

**我说的**：

> https://github.com/ZhanJHE/online-games.git，这是我的仓库，帮我传上去，配置一下

**AI 做的**：推代码、开 GitHub Pages、把仓库描述和主页链接填好、给仓库加了几个 topic、生成了微信分享用的缩略图，然后自己打开线上地址跑了 5 个页面截图给我看。

**我的判断**：第一次看到自己的链接能打开，说实话有点爽。但我注意到分享到微信时没有缩略图，后来让它把 `og:image` 改成绝对地址。

---

## 第 4 轮：加赞赏码

**我说的**：

> 我在根目录下放了 我的打赏二维码，帮我加到页面上，二维码放最后测试出结果的时候的最下面

**AI 做的**：把根目录的图挪到 `assets/img/`，在结果页最底部加了一块，虚线分隔、居中小字。还把图片做了懒加载，说“不进结果页就不会下载”。

**我的判断**：位置可以，但放在每一次结果的最后，意味着每测一次都会被摆到眼前。这让我有点不舒服，后面就撤了（见第 7 轮）。

---

## 第 5 轮：从“一个测评”变成“一个合集”

**我说的**：

> 用 Github Pages 做一个小游戏合集，做 7 个小游戏 + 1 个关于，进去首页上面写着小游戏合集，下面八个长方形框（上 4 个，下 4 个，其中右下角那个是关于，其他的是游戏），点开任意一个框就能跳到小游戏，我能想到的就俄罗斯方块、XX 转盘、还有刚才的那个塔罗牌，剩下的你想，不用太复杂

**AI 做的**：

- 把原来的塔罗页整个搬进 `/tarot/`，游戏各自一个目录
- 七个游戏全部手写：俄罗斯方块、恋爱转盘、塔罗、2048、记忆翻牌、贪吃蛇、扫雷
- 首页做成 4×2 的卡片网格
- 顺手处理了一个我没想到的问题：老的分享链接是根路径 `?r=moon`，搬目录后会失效，所以在首页加了一段转发，旧链接自动跳到新地址

**我的判断**：“剩下的你想”这句其实很考验 AI 的选择——它给的是 2048、记忆翻牌、贪吃蛇、扫雷，都是不用美术资源、单个文件能写完的，符合我说的“不用太复杂”。

**这轮出了问题**：我看截图时发现记忆翻牌的牌面全叠在一起，扫雷的棋盘只有一半大。AI 查出来是**类名撞车**——翻牌的“牌背”用了 `.back`，跟公共样式里“返回”链接的 `.back` 撞了；扫雷的棋盘宽度被外层布局压扁了。这类问题我自己绝对查不出来，只能看出“不对劲”。

---

## 第 6 轮：我让它挑自己的毛病

**我说的**：

> 帮我想想这个界面美观上还有没有什么优化的空间？

**AI 做的**：给了一份很具体的清单，比我预期的狠：

- 卡片说明、游戏提示用的灰色在浅底上对比度只有 2.8:1，低于无障碍标准，字号 11.5px 也偏小
- 游戏画布直接浮在背景上，没有“托底”
- 八个游戏没有任何识别色，进去都一样
- 全站没有键盘焦点样式，Tab 走一遍看不见光标在哪
- 手机上的按钮只有 40px 高，低于 44px 的触控建议值
- 2048 的数字是“跳”过去的，没有动画

**我的判断**：这些我大多没意识到，但我能判断哪些值得改。对比度和触控尺寸属于“不改就是缺陷”，主题色属于“改了体验明显不一样”，所以我回复了「就这样改」。

**结果**：计分牌挪到页面上方、数字放大、每个游戏一个主题色、画布外面套纸面板、按钮加到 44px、加了错开淡入和结束遮罩动画、2048 加了新块和合并的动画。

**又修了一个我自己没发现的问题**：转盘左半边和下半边的字是倒的（中文旋转 180 度特别难看）。最后干脆改成全部水平摆放。

---

## 第 7 轮：隐私处理，这次是我提的

**我说的**：

> 就这样改，然后先把收款码和 关于 部分暂时先屏蔽掉，这部分有些问题（个人问题），云端仓库的git旧提交也删掉

**AI 做的**：把关于页换成“暂时关闭”，首页撤掉入口（换成“更多在路上”占位卡），结果页删掉赞赏码，把二维码图片从 git 移除并写进 `.gitignore`，然后把历史压缩成单次提交、强推覆盖。

**它主动告诉我的事**：旧提交在 GitHub 上用链接还能打开（它试了，返回 200），要彻底清掉得删库重建，需要我授权。这一点我不懂，但它说清楚了代价，我就知道该怎么决定。

**这件事的收获**：让 AI 干活的时候，它愿意主动说“我做到的和你以为我做到的，不是一回事”，这比多写两个功能有价值。

---

## 第 8 轮：换新码，放回关于页

**我说的**：

> 还有这个赞赏码我已经更新了，用这个码吧，放到关于里，让它上线

**AI 做的**：

- 检查发现新图其实是 WebP 格式但后缀写成了 `.png`，浏览器虽然一般能认，但服务器的 MIME 会说错，所以它把图转成了真正的 PNG 再放进去
- 关于页恢复完整内容，赞赏码放在最底部（不再放结果页）
- 首页右下角换回“关于”
- 跑一遍自动检查：9 个页面、点开赞赏码确认图片真的加载出来了（不只是看标签存在）

**我的判断**：这次位置对了——想打赏的人点进“关于”自己会看到，不想看的人玩游戏时不会被打扰。

---

## 我总结出的四条经验

1. **说清楚给谁看、在什么场景看**。我一开始说“手机上点开就能玩”，它就没往桌面端大布局上跑偏。
2. **描述现象比描述方案有用**。我不会说“修改 canvas 旋转矩阵”，但我能说“左边的字是倒的”，效果一样。
3. **让它自己验证，比我说“好像不太对”快**。它会打开浏览器点一遍再截图，很多问题在给我看之前就被它自己抓到了。
4. **拿不准的事让它解释，别让它猜**。比如“这个页面是怎么组织的，用我能听懂的话说一遍”，比让它自己发挥靠谱。

## 我还没解决的问题

- GitHub 上的旧提交还能通过链接访问，我没删库
- 分数只存在浏览器里，换设备就没了
- 没有音效，2048 的位移动画也没做全
